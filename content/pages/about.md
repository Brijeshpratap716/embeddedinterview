EmbeddedInterview.com is a free resource for engineers preparing for embedded software, firmware, BSP and Linux kernel interviews.

## Who writes it

I'm **Brijesh Pratap Singh**, a senior embedded software engineer with about **7 years of experience** across bare-metal firmware, the Linux kernel, device drivers and virtualization.

- **Qualcomm** — Senior Engineer, display and touch drivers (DRM/KMS, MIPI DSI).
- **Boeing** — QEMU/KVM virtualization.
- **Intel** — graphics driver debugging.
- **Cyient** — bare-metal firmware.

In embedded interviews the same topics come up again and again: `volatile`, interrupts, pointers and memory, bit manipulation, RTOS synchronisation, I2C/SPI/UART/CAN, the Linux driver model, and coding rounds with ring buffers, linked lists and memory allocators. Most material I found online either stopped at one-line answers or was written for web developers, so I started writing the answers I wish I had read before my own interviews.

## How the content is written

- **Short answer first, then the detail.** Every question starts with the two or three sentences you would actually say in an interview, followed by the explanation, a worked example, the code and the follow-up questions interviewers ask next.
- **Embedded first.** Registers, ISRs, DMA, caches, RTOS behaviour and kernel internals, not generic programming trivia.
- **Tested code.** Every practice problem's reference solution compiles cleanly with `-Wall -Wextra` and passes its tests, and the C examples in the answers are compiled and run before they are published.
- **Free, no sign-up.** Your progress is stored in your own browser.

## Found a mistake?

Embedded systems are full of "it depends". If you spot an error, disagree with an answer, or want to suggest a question from an interview you faced, please [get in touch](../contact/). Corrections from readers make the site better for everyone.
